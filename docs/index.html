odd-pilot

Make every driving-simulation test count: check scenarios against the laws of physics before you run them, measure how much of the real world your tests actually cover, and generate exactly the tests you are missing.

The problem, in one number

Teams test automated-driving software in simulators, using thousands of automatically generated scenarios. We audited the standard generation approaches and found that almost every generated scenario is physically impossible — heavy rain over a bone-dry road, a blazing sun at midnight, braking harder than any tire can grip. A failure found in an impossible world tells you nothing about the real one.

98.6%of randomly generated scenarios violate physics
100%of adversarially searched scenarios do
0%when odd-pilot generates and checks them

What odd-pilot does

1 · Check

The built-in linter, physcheck, reads each scenario file and flags everything physically impossible or inconsistent — with a literature citation attached to every rule, like a spell-checker for physics.

2 · Measure

assess compares what you have tested against how the real world actually behaves (learned from recorded driving data) and answers one question: have we tested enough, and if not, what is missing?

3 · Generate

plan creates the next batch of scenarios aimed precisely at the gaps, keeps them realistic, and physics-checks every one before it ever reaches your simulator.

One campaign iteration looks like this — and the loop command can drive the whole cycle for you:

check→ run in simulator→ measure coverage→ generate the missing tests→ repeat until enough

What gets checked

physcheck looks at a scenario through seven independent lenses, from simple to sophisticated. You can use any subset; nothing else is required.

LayerPlain-language question it asks
L0 · FormatIs the file well-formed, are values inside their legal ranges?
L1 · Weather physicsDo the conditions make sense together — can it rain from a clear sky, snow in summer heat, fog with 50 km visibility?
L2 · MapDo the cars start on real roads of the map, is the sun where it could ever be in that sky, are speed limits respected?
L3 · MotionCould real tires do this — the braking, the cornering speed, the lane change? Do recorded trajectories teleport?
L4 · Story logicCan every scripted event actually happen, or does the scenario contradict its own timeline?
L5 · Operating domainDoes the scenario stay inside the conditions your system is declared to handle (its ODD)?
L6 · RealismEven if possible — does this combination ever actually occur in real driving?

Reading the results

You seeIt means
ERRORPhysically impossible or contradictory as written — fix it before trusting any result from it.
WARNINGSuspicious or extremely rare — worth a deliberate look, never blocks you.
ADEQUATEYour executed tests sufficiently cover the expected real-world operation — the campaign may stop.
INADEQUATECoverage gaps remain; gaps lists them, plan closes them.
IN / OUT / UNDECLAREDWhether a scenario stays inside your declared operating domain, leaves it, or doesn't say.

Every finding names its rule, explains itself in a sentence, and cites the physical literature or standard it is based on. Reports come out as readable tables, web pages, or CI-ready formats.

Get started

# install (Python 3.10+)
pip install -e physcheck/ -e odd-pilot/

# 1 · check a folder of scenarios — the only command many teams need
odd-pilot lint my_scenarios/

# 2 · learn how the real world behaves from recorded driving data (CSV)
odd-pilot model fit --data driving_records.csv -o world.bn

# 3 · have we tested enough?
odd-pilot assess --model world.bn --log test_runs.csv --t 2

# 4 · what's missing, and generate 20 realistic tests to fix it
odd-pilot gaps --model world.bn --log test_runs.csv --t 2
odd-pilot assess ... --json adequacy.json
odd-pilot plan --model world.bn -a adequacy.json -k 20 \
    --template my_template.xosc -o next_batch/

# 5 · one evidence document for the safety case
odd-pilot report -a adequacy.json -o evidence.md

Can I trust it?

  • Validated on real driving data: across 1,109 scenario files derived from real recorded traffic (drone, camera and roadside-sensor datasets), the checker raised zero false alarms — while detecting all 1,819 deliberately injected impossibilities.
  • Every rule is cited: all 157 checks carry a reference to primary literature or standards — tire friction handbooks, atmospheric optics, solar ephemerides, ISO 21448/34503.
  • It audits its authors too: during development the checker caught several bugs in our own "carefully crafted" scenarios — which is rather the point.

Standards & formats

Scenarios: ASAM OpenSCENARIO 1.0–1.3 · Maps: ASAM OpenDRIVE · ODD definitions: YAML with OpenODD-style include/exclude conditions · Reports: table, HTML, JSON, SARIF, Markdown/PDF evidence artifacts. Works with any simulator — odd-pilot never touches one directly.
