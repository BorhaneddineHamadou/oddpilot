physcheck — every rule, explained

The physical-plausibility linter inside odd-pilot. What it is

physcheck is a linter: it never runs a simulation. It parses each scenario file, reconstructs what the file actually declares — weather, road surface, actors, motion, story logic — and evaluates rules against that declaration. A finding always carries: the rule id, a severity (error = impossible as written, warning = suspicious or rare, info = worth knowing), a one-sentence message with the offending values, and the literature source the rule is based on.

The severity philosophy is deliberate: errors are reserved for the certainly-impossible. Where physics gives a range, rules use the generous end of the published range, so an error means "no real-world configuration could produce this file" — not "unusual".

ComponentWhat it does, in practice
ParserReads OpenSCENARIO 1.0–1.3, resolves $parameters, ${expressions} and catalog references. It never throws: anything it cannot interpret becomes an L0 finding, so one broken element never hides the rest of the file.
Scenario IRA typed, engine-agnostic model of the file: environments, entities with performance and boxes, speed commands, lane changes, followed trajectories (memory-efficient for replay files with 100,000+ vertices), and the storyboard control structure.
Attribute viewThe IR flattened into canonically named values (env.precip.type, entity.max_decel_mps2, …). YAML rules only ever see this view — never raw XML. An absent value is an absent key, never a default: a rule that needs a missing attribute silently does not apply.
YAML rules (116)Each is a guarded predicate in a safe expression subset (comparisons, arithmetic, a fixed set of math functions — no arbitrary code). Shown below per rule as "Applies when" / "Requires".
Built-in analyses (41)Checks that need real computation: the OpenDRIVE map frontend (geometry sampling, lane resolution, connectivity), the NOAA/Meeus solar ephemeris, trajectory kinematics with noise-robust windowed estimators, storyboard reachability, ODD evaluation, and the statistical scorer. Each is documented with its rules below.
Layer gatingLayers are independent and opt-in: L0–L1 always work from the file alone; L2–L3 activate when a map is available (via --map or the scenario's own RoadNetwork reference); L5 needs an ODD definition; L6 an operational model. Missing inputs skip a layer with a note — never an error.
DeterminismSame inputs, same findings: no randomness, no network, no simulator. Suitable as a CI gate (--fail-on error sets the exit code).

Every interpretation decision made while implementing the rules (what a missing attribute means, which frame a coordinate is in, how tolerances were chosen) is recorded in docs/decisions.md (D1–D36) — the reviewers' trail behind every threshold on this page.

Using it

# check a folder — layers L0+L1 need nothing but the files
physcheck lint scenarios/

# add map-based checks (L2+L3): give a map, or let each file's
# RoadNetwork reference resolve automatically
physcheck lint scenarios/ --map town04.xodr

# storyboard logic, ODD conformance, statistical realism
physcheck lint scenarios/ --layers L0,L1,L4
physcheck lint scenarios/ --odd my_odd.yaml
odd-pilot lint scenarios/ --layers L0,L1,L6 --model world.bn

# outputs and CI
physcheck lint scenarios/ --format sarif -o lint.sarif   # GitHub code scanning
physcheck lint scenarios/ --format html  -o report.html  # shareable page
physcheck lint scenarios/ --fail-on error                # exit 1 on any error

# understand a finding
physcheck rules show FRI-013
physcheck lint s.xosc --explain FRI-013

Exit codes: 0 clean, 1 findings at/above --fail-on, 3 usage error. 2 is reserved by odd-pilot's assess --fail-if-inadequate.

Writing your own rules

Teams add domain rules without touching code — a YAML pack with the same schema as the built-in catalog, validated by physcheck rules lint:

pack: my_team
version: "1.0"
rules:
  - id: TEAM-001
    layer: L1
    severity: error
    title: Our simulator cannot render fog below 50 m
    scope: scenario
    when: "env.fog.present"
    assert: "env.fog.visual_range_m >= 50"
    message: "visualRange={env.fog.visual_range_m} m is below the renderer's floor."
    units: {env.fog.visual_range_m: m}
    citation: {source: "Internal renderer spec RD-42", year: 2026}

# validate, then use it
physcheck rules lint my_rules.yaml
physcheck lint scenarios/ --rules my_rules.yaml

Validation

physcheck is benchmarked on every release against scenario files derived from real recorded driving (drone recordings of intersections and motorways, camera recordings, roadside-sensor replays): real driving is physically plausible by construction, so every error finding there is a potential false alarm — and there were 0 tool false alarms across 1,109 files, while all 1,819 deliberately injected impossibilities were detected. The full protocol, corpora provenance and per-finding triage evidence live in the benchmark repository.

L1 · Atmosphere 7 rules · YAML pack atmosphere.yaml

Atmospheric optics and thermodynamics: fog versus visual range, cloud cover versus sunlight, temperature versus pressure. Derived from meteorology and atmospheric-optics literature.

ATM-001 warning L1 · per scenario

Fog declared but visual range is not fog

Applies whenenv.fog.present
Requiresenv.fog.visual_range_m < 1000

Aeronautical code FG requires MOR < 1000 m; BR (mist) 1000-5000 m.

Source American Meteorological Society, 'fog', Glossary of Meteorology, 2nd ed.; WMO, Guide to Instruments and Methods of Observation, WMO-No. 8, Vol. I, Ch. 9 (Measurement of visibility) (2021) — https://glossary.ametsoc.org/wiki/Fog

ATM-002 error L1 · per scenario

Visual range beyond the Rayleigh-scattering limit of air

Applies whenenv.fog.present
Requiresenv.fog.visual_range_m <= 350000

Rayleigh beta ~0.0116 km^-1 at 550 nm sea level: max MOR = 2.996/0.0116 ~258 km (WMO eps=0.05) or 3.912/0.0116 ~337 km (classical eps=0.02).

Source Penndorf, R., Tables of the refractive index for standard air and the Rayleigh scattering coefficient..., Journal of the Optical Society of America 47(2):176-182; Middleton, W.E.K., Vision Through the Atmosphere, Univ. of Toronto Press (1952) (1957) — https://doi.org/10.1364/JOSA.47.000176

ATM-003 warning L1 · per scenario

Visual range too high for the declared rain rate

Applies whenenv.precip.type == 'rain' and env.precip.intensity_mmh >= 5 and env.fog.present
Requiresenv.fog.visual_range_m <= 40000 * env.precip.intensity_mmh ** -0.55

Weakest corner (a=0.15, b=0.55) with WMO MOR = 2.996/sigma gives ~19.97*R^-0.55 km; predicate doubles it. At R=50 mm/h the bound is ~4.6 km; a declared 10 km is flagged.

Source Atlas, D., Optical extinction by rainfall, Journal of Meteorology 10(6):486-488; disdrometer sigma-R studies (Atmosfera 39, 2025) (1953) — https://doi.org/10.1175/1520-0469(1953)010<0486:OEBR>2.0.CO;2

ATM-004 warning L1 · per scenario

Visual range too high for the declared snowfall rate

Applies whenenv.precip.type == 'snow' and env.precip.intensity_mmh >= 0.5 and env.fog.present
Requiresenv.fog.visual_range_m <= 10000 / env.precip.intensity_mmh

At 1 mm/h LE, visibility ~1 km; inverse proportionality with crystal-type spread 3-10x.

Source Rasmussen, R.M., Vivekanandan, J., Cole, J., Myers, B., Masters, C., The Estimation of Snowfall Rate Using Visibility, Journal of Applied Meteorology 38(10):1542-1563 (1999) — https://doi.org/10.1175/1520-0450(1999)038<1542:TEOSRU>2.0.CO;2

ATM-005 warning L1 · per scenario

Liquid fog below the homogeneous freezing point

Applies whenenv.fog.present and env.fog.visual_range_m < 1000

L1 · Road friction 23 rules · YAML pack friction_road.yaml

The precipitation → wetness → friction chain: what tire–road friction is possible on the declared surface, and what braking/acceleration that permits. Grounded in vehicle-dynamics handbooks (Pacejka, Gillespie, Bosch) and road-friction measurement studies.

FRI-001 error L1 · per scenario

Wet or moist road cannot exceed dry-baseline friction

Applies whenenv.road.wetness != 'dry'
Requiresenv.road.friction_scale <= 1.0

Bosch: mu drops from ~0.85 (dry, 50 km/h) to ~0.65 with 0.2 mm water film and ~0.55 with ~1 mm film.

Source Robert Bosch GmbH, Automotive Handbook, 4th ed., p. 330 (tire friction table); Hall, J.W. et al., Guide for Pavement Friction, NCHRP Web-Only Document 108, TRB (2009) — https://doi.org/10.17226/23038

Applies whenenv.road.wetness == 'dry' and env.precip.type == 'dry'
